Arquitetura

API e worker saem da mesma imagem. Postgres guarda outbox, master, dead letters e erros; Redis segura a fila BullMQ.

Recepção (POST)

A recepção só grava a intenção e responde. Nada externo é chamado aqui.

sequenceDiagram
  autonumber
  participant C as Cliente
  participant A as API
  participant DB as Postgres
  participant Q as BullMQ/Redis
  C->>A: POST /notifications
  A->>A: ValidationPipe (whitelist, forbidNonWhitelisted)
  alt payload inválido
    A->>DB: INSERT error_logs (http, 400)
    A-->>C: 400 com errorId
  else chave nova
    A->>DB: INSERT outbox_events (pending)
    A->>Q: add job (jobId = idempotencyKey)
    A-->>C: 201 pending
  else chave repetida ou P2002
    A->>DB: SELECT status
    A-->>C: 200 com status atual, sem job
  end

Worker

Ordem fixa: webhook, Resend, master. Master só é escrito no fim.

sequenceDiagram
  autonumber
  participant Q as BullMQ
  participant W as Worker
  participant DB as Postgres
  participant H as Webhook
  participant R as Resend
  Q->>W: job idempotencyKey
  W->>DB: carrega outbox
  opt status committed
    W-->>Q: encerra sem efeito
  end
  W->>DB: processing, attemptCount + 1
  W->>H: POST WEBHOOK_URL (timeout 5s)
  alt fora de 2xx ou timeout
    W->>DB: step webhook, lastError, INSERT error_logs
    W-->>Q: falha, retry com backoff
  end
  W->>R: emails.send (Idempotency-Key)
  alt erro da API
    W->>DB: step resend, lastError, INSERT error_logs
    W-->>Q: falha, retry com backoff
  end
  W->>DB: transação: INSERT master_records e committed
  W-->>Q: concluído
  Note over Q,DB: Na 5a falha: outbox failed e INSERT dead_letters

Estados do outbox

stateDiagram-v2
  [*] --> pending: POST 201
  pending --> processing: worker pega o job
  processing --> processing: falha webhook ou resend, retry
  processing --> committed: master gravado
  processing --> failed: 5 tentativas esgotadas
  committed --> [*]
  failed --> [*]

Tratamento de erros

Todo erro vai para error_logs no mesmo Postgres. Falha ao gravar o log nunca muda a resposta nem o job.

flowchart LR
  e["Exceção"] --> o{"Origem"}
  o -->|"HTTP"| f["AllExceptionsFilter"]
  o -->|"Worker"| wf["WorkerFactory"]
  f --> ins["INSERT error_logs"]
  wf --> ins
  ins -->|"ok"| r["Resposta com errorId ou retry do job"]
  ins -->|"falha"| s["Log em stdout, errorId nulo, status original"]
  wf -->|"última tentativa"| dl["INSERT dead_letters e outbox failed"]

Modelo de dados

Um Postgres, quatro tabelas. A ligação é lógica pelo idempotencyKey, sem FK.

erDiagram
  outbox_events ||--o| master_records : "idempotencyKey"
  outbox_events ||--o{ dead_letters : "idempotencyKey"
  outbox_events ||--o{ error_logs : "idempotencyKey opcional"
  outbox_events {
    uuid id PK
    string idempotencyKey UK
    json payload
    string status
    string step
    int attemptCount
    string lastError
    timestamp createdAt
    timestamp updatedAt
  }
  master_records {
    uuid id PK
    string idempotencyKey UK
    json payload
    timestamp createdAt
  }
  dead_letters {
    uuid id PK
    string name
    string idempotencyKey
    string step
    string error
    json payload
    timestamp createdAt
  }
  error_logs {
    uuid id PK
    string source
    string idempotencyKey
    string step
    int statusCode
    string message
    string stack
    json context
    timestamp createdAt
  }
